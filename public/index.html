START WITH CONFIDENCE

Your first session, step by step.

From a fresh install to a repeatable multi-device workflow.

01 · Prepare your computer02 · Connect your project03 · Prepare a device04 · Debug in your editor05 · Save your everyday device set06 · Read device system logs07 · Capture and share a result08 · When something needs attention
01

Prepare your computer

Install Flutter and Android SDK for Android devices on macOS or Windows. For iOS Simulator, use macOS with Xcode, its command-line tools and an installed iOS runtime. Windows cannot run iOS Simulator.

Check each tool, accept Android SDK licenses and save custom SDK paths in Preferences if detection fails.
02

Connect your project

Choose the folder containing pubspec.yaml. Import a VS Code debug profile or select the flavor, Dart entrypoint and defines file. Snapkit stores these choices locally without changing your source or launch.json.

Moved your project? Choose its new folder again. Saved device sets belong to the original folder; Snapkit does not scan your disks to relocate source code.
03

Prepare a device

Use Add device to choose a compatible model and OS, then start it. For Android phones, enable USB debugging and approve this computer. For iPhone, enable Developer Mode, trust your Mac and configure signing in Xcode.

Android Wi-Fi: pair and connect using Android Studio Wireless debugging first. Keep both devices on the same stable network. Wi-Fi speed depends on your network; USB can be faster.
04

Debug in your editor

In VS Code, Cursor or Antigravity, install Snapkit Debug Sync and the Dart/Flutter extensions. Open the same project, select online devices in Snapkit and press F5 in your normal Flutter profile.

Android Studio and IntelliJ use their own device selector and debug controls. Hot Reload, Dart output and DevTools stay in your IDE. A new Snapkit selection applies to the next debug run.
05

Save your everyday device set

Create a named set for the current project, such as Phone + tablet. Include virtual devices that are currently off. Start the set to boot up to two devices at a time and follow each result.

Physical phones must already be connected. Missing devices are reported individually. Use Select ready devices for IDE after startup; starting a set does not alter an existing debug session.
06

Read device system logs

Select an online Android device or iOS Simulator, then start logs. Search by app name, package or message and filter warnings/errors. Pause following to read a line, or export the visible filtered log.

These are system logs, not the Flutter Debug Console. Keep the IDE open for Dart print output. Snapkit retains the latest 1,000 lines per stream and stops streams without a viewer after one minute.
07

Capture and share a result

Take a PNG screenshot or record an MP4 from a supported online device. Stop recording to finalize the file before downloading. Captures are stored separately for each project in Snapkit data.

Recordings are limited to 3 minutes, with at most two running at once. Physical iPhone capture and logs require Xcode or QuickTime. Recordings do not include audio; protected screens may appear blank.
08

When something needs attention

If a device is missing, unlock it, check trust or USB debugging and refresh Devices. If tools are missing, verify SDK paths. If debug targets do not apply, check the project folder and Snapkit extension in your editor.

Internet is required for account verification. Device commands and source stay on your computer. Keep enough free disk space for emulator data and recordings; delete saved captures when no longer needed.
