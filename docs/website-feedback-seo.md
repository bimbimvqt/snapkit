# Website feedback and search

The landing page at https://snapkit.vn/#feedback accepts star ratings (1–5) and reviews, bug reports, feature requests and other feedback. Name and email are optional. Messages are 10–4,000 characters. Feedback is stored in the cloud data volume's accounts.json through the existing serialized, atomic account transaction. Do not replace or check in this data file during deployment.

Administrators can read the newest 50 submissions at a time and change their status (New, Reviewing, Done) in https://snapkit.vn/admin/. Bug reports, feature requests, other feedback and all email addresses remain private. A review is public only when the sender opts in to publication and an administrator explicitly approves it. Legacy submissions have no publication permission and remain private. Processing status (New, Reviewing, Done) is independent of moderation (Pending, Approved, Rejected). Administrators can withdraw approval to remove a public review. The public API exposes only name, message, rating, id and date; it never includes email or account/audit fields. The public form uses same-origin requests, field validation, a honeypot and a five-submission-per-IP hourly limit in each service process. That limit resets when the service restarts; monitor abuse before scaling beyond a single service. There is no automated email delivery.

SEO includes a descriptive title/description, canonical URL, Open Graph/Twitter image metadata, WebSite and SoftwareApplication JSON-LD, robots.txt and sitemap.xml. No ratings or reviews are included in structured data. The review list contains only consented, approved submissions; empty states contain no invented testimonials. Old GitHub Pages landing bookmarks redirect to snapkit.vn; paired controllers keep their existing routes. Internal account/admin/controller/demo pages send noindex headers. Main content remains readable in the initial HTML.

After deployment, verify ownership of snapkit.vn in Google Search Console, submit https://snapkit.vn/sitemap.xml, and request indexing of the home page. This requires the site owner's Google account and cannot be replaced by adding keywords. Rankings and indexing dates are controlled by search engines; no tags guarantee position one. Content about specific supported workflows and relevant external links should be grown over time. The separate Swift library named SnapKit competes for the same brand query, so prioritize phrases such as "Snapkit Flutter", "Flutter multi-device debugging" and "React Native device manager" with accurate visible content.

To refresh the gallery: SNAPKIT_REFRESH_WEBSITE=1 npx playwright test --config playwright.pages.config.js tests/pages/refresh-assets.spec.js. The capture test verifies active navigation and waits for transitions to finish. When publishing new images, update the gallery query version in site.js/index.html and corresponding page test expectations.

## Search pages (2026-11-06)

`npm run build:pages` uses `scripts/build-seo-pages.js` and the authored bilingual content in `scripts/content/seo-guides.js` to create 12 indexable URLs: Vietnamese and English landing pages, two guide indexes and four guides in each language. Every public page has a self-canonical, reciprocal vi/en/x-default alternates and initial HTML content. English is rendered at build time; the optional page-language/reverse lookup in shared i18n preserves the existing interactive language switch without changing dashboard locale behavior. Query-language variants canonicalize to their owning page. No automatic IP-based or browser-language redirect is used on these public pages.

The generated sitemap replaces the single-URL source fallback. Guides use TechArticle and BreadcrumbList schema without fabricated authors, reviews or ratings. Content covers Flutter multi-device selection, React Native CLI/Metro/Hermes requirements and limitations, Android/iOS virtual devices and installation/signing requirements. Edit the content module and rebuild rather than editing generated HTML in `dist/`.

Google's provided verification token is public in the HTML meta tag and an additive apex TXT record. Keep the TXT record after verification. Search Console verification does not mean URLs have been indexed. Submit `/sitemap.xml` from the verified Domain property, inspect the home page and request indexing, then monitor Search Console coverage, non-brand impressions/clicks, CTR and query/page performance. Google may take time to report data and does not guarantee inclusion or rankings.

Private account/admin HTML and generated demo/controllers include noindex meta tags in addition to server headers. Demo/controller routes are crawlable so search crawlers can see noindex; API/auth/admin paths remain disallowed. Public images use WebP for gallery/guide delivery (PNG remains for social images), with explicit dimensions and lazy loading where appropriate. Public assets have bounded browser caching; HTML and account/API responses retain no-store. No Google Analytics tag or advertising tracker is added without an actual configured property. Download conversion attribution is not measured by Search Console; use a separately configured analytics property if needed.

After refreshing PNG screenshots using the command above, regenerate the matching WebP files before publishing. The generated docs and landing gallery read WebP; social cards use PNG. Keep the gallery cache query version consistent with the page tests.
